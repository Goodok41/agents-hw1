# Design: harden-agent

## Context

`agent.py` — однофайловый агент без зависимостей. Цикл `run_agent` вызывает модель, исполняет
`search_docs`/`read_doc` через `run_allowed_tool`, пишет трассу и проверяет ссылки финального ответа.
Ограничения: Python 3.11+, без сети в тестах, интерфейс инструментов и `--replay` не меняются.

## Goals / Non-Goals

**Goals:** R1–R6 из брифа; тестируемость A1–A5 через заглушки модели и инструмента.

**Non-Goals:** изменение поиска, промпта SYSTEM, live-клиента, лимитов в `config.json`, формата `REPLAY_RESPONSES`.

## Decisions

1. **R1 — `not_found` с `doc_id`.** В ошибку `read_doc` добавляется поле `doc_id`; `run_agent`
   собирает `missing_ids` из событий с `error.code == "not_found"`. Схема инструмента не меняется (R6).
2. **R2 — внедряемый исполнитель инструментов.** `run_agent(..., tool_fn=run_allowed_tool)`;
   вызов обёрнут в `try/except Exception` → `{"error": {"code": "tool_failure", "message": "<Тип>: <текст>"}}`.
   Параметр `tool_fn` нужен тестам A4 для искусственного сбоя. Сбойный вызов засчитывается в `tool_calls`
   (лимит не обходится). Нестроковые `arguments` больше не считаются фатальной ошибкой протокола:
   они доходят до инструмента и дают `bad_arguments` (A3). Некорректные `id`/`type` вызова по-прежнему дают `AgentError`.
3. **R3 — статус и сводка.** `status = "error"`, если в результате есть ключ `error`, иначе `"ok"`.
   Единая функция `finish(stop_reason, model_calls, answer)` формирует результат и добавляет
   `read_ids` (sorted), `missing_ids` (sorted), `tool_errors` во всех ветках выхода.
4. **R4 — проверка источников.**
   - Ссылки извлекаются шире: любой токен `D\d{2}` как отдельное слово (`\bD\d{2}\b`), а не только `[D01:` / `(D01)`.
   - Неподтверждённые ID = ссылки − `read_ids`. Прежние условия (не было поиска; поиск нашёл документы, но ничего не прочитано)
     сохраняются. Все они — один тип нарушения с общим счётчиком замечаний.
   - Текст замечания перечисляет конкретные ID (неподтверждённые ссылки, а если их нет — найденные поиском, но непрочитанные).
   - `MAX_SOURCE_REMARKS = 2`; при третьем нарушении — `unverified_sources`, `answer = None`.
   - Replay использует 1 замечание, поэтому его поведение не меняется.
5. **R5.** Проверки бюджета не трогаются; `budget_exhausted`/`tool_budget_exhausted` идут через `finish`.
6. **Вывод `main`.** Дополнительно печатаются `read_ids`, `missing_ids`, `tool_errors`; для `unverified_sources`
   выводится понятное сообщение.

## Risks / Trade-offs

- Более широкое распознавание ссылок может отклонить ответ, где ID упомянут в тексте без цитирования
  (например, «D99 не найден»). Это соответствует строгой формулировке R4 («не может ссылаться»).
- Тест A2 проверяет конвейер (доказательства и отказ от неподтверждённых ссылок), а не честность живой модели.
