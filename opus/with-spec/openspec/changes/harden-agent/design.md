# Design: harden-agent

## Context

Весь агент — один файл `agent.py` без зависимостей. Цикл живёт в `run_agent(question, cfg, model_fn, mode, emit)`, инструменты — в `run_allowed_tool(name, arguments, docs)`. Модель передаётся функцией `model_fn(history, tools) -> (reply, usage)`, поэтому тесты подставляют заглушку без сети.

## Goals / Non-Goals

**Goals:** R1–R6 из change-brief.md; минимальные точечные правки; вывод `--replay` в консоль не меняется.

**Non-Goals:** новые инструменты, изменение CLI, изменение лимитов в `config.json`, изменение живого клиента API.

## Decisions

### D1. Ошибка not_found (R1)
`run_allowed_tool` уже возвращает `{"error": {"code": "not_found", ...}}`. Добавляем в ошибку поле `doc_id` (дополнительное поле, успешный формат не меняется). `missing_ids` собирается в `run_agent` по событиям `tool` с `name == "read_doc"` и кодом ошибки `not_found`; ID берётся из `result["error"]["doc_id"]`.

### D2. Изоляция исключений (R2)
Вызов инструмента в `run_agent` обёрнут в `try/except Exception` (не `BaseException`, чтобы Ctrl+C работал). Исключение превращается в `{"error": {"code": "tool_failure", "message": "<Тип>: <текст>"}}`. Вызов засчитывается в `tool_count`. Функция инструмента передаётся в `run_agent` необязательным параметром `tool_fn=run_allowed_tool` — это позволяет тестам внедрить сбой без monkeypatch; по умолчанию поведение прежнее.

### D3. Статус и сводка (R3)
При записи события `tool` добавляется `status = "error" if "error" in result else "ok"`. Все пути выхода из `run_agent` идут через локальную функцию `finish(stop_reason, model_calls, answer=None)`, которая добавляет `read_ids`, `missing_ids` (оба `sorted(set(...))`) и `tool_errors` (число событий со статусом `error`). Так поля гарантированно есть при любой причине остановки.

### D4. Проверка источников (R4)
- Цитируемые ID: все токены `D\d{2}` в ответе (регулярное выражение `(?<![A-Za-z0-9])D\d{2}(?!\d)`), а не только первый в скобках — строже прежнего.
- Прочитанные ID: только `read_doc` со статусом `ok`.
- Ответ не проходит, если: не было `search_docs`; есть цитируемые непрочитанные ID; поиск что-то нашёл, но ничего не прочитано (прежние условия сохранены).
- Счётчик `remarks`. Если ответ не прошёл и `remarks < 2` — модели отправляется замечание с перечислением конкретных ID (непрочитанные цитируемые, а если их нет — найденные поиском, но не прочитанные), в журнал пишется событие `validation` с `ids`, `remarks += 1`. Если `remarks == 2` — `finish("unverified_sources", ...)`, `answer = None`.
- Строка консоли `[проверка] Источники ещё не прочитаны. Нужен read_doc.` сохраняется, чтобы не менять вывод `--replay`.

### D5. Лимиты (R5)
Логика лимитов не меняется: проверка `tool_count + len(calls) > max_tool_calls` до выполнения пакета и `budget_exhausted` после `max_model_calls` шагов. Меняется только сбор результата через `finish`.

### D6. Совместимость (R6)
`TOOLS`, аргументы инструментов и формат успешных результатов не меняются. `REPLAY_RESPONSES` и `main()` не меняются. Регрессия проверяется тестом и сравнением консольного вывода с эталоном до изменения.

## Risks / Trade-offs

- Более строгий поиск ID может отклонить ответ, который упоминает ID без ссылки (например, «см. D06»). Это соответствует R4: ссылаться можно только на прочитанное.
- Ограничение в 2 замечания может остановить ответ раньше, чем раньше (до исчерпания бюджета) — это требование R4.
