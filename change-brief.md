# Изменение для обеих попыток (direct и with-spec)

Стартовый код: python-agent/ из архива ДЗ (agent.py, docs.json, config.json), хеши в base.sha256.
Изменение: явная обработка отсутствующего документа и проверка источников.

- R1. Неизвестный doc_id в read_doc даёт структурированную ошибку not_found; ID попадает в missing_ids.
- R2. Исключение внутри инструмента не роняет процесс: оно превращается в результат
  {"error": {"code": "tool_failure", ...}}, цикл продолжается в рамках лимитов.
- R3. Журнал: у каждого события tool есть status ("ok" или "error"). В итоговом результате есть
  read_ids (успешно прочитанные, по возрастанию), missing_ids и tool_errors (число ошибок инструментов).
- R4. Проверка источников: финальный ответ не может ссылаться на ID, который не был успешно прочитан.
  Программа возвращает модели замечание с конкретными ID не более 2 раз за запуск; после этого
  stop_reason = "unverified_sources", answer = null. Неподтверждённый ответ не выдаётся.
- R5. Лимиты не ослабляются: исчерпание вызовов модели или инструментов даёт
  budget_exhausted / tool_budget_exhausted, answer = null.
- R6. Интерфейс search_docs/read_doc и поведение --replay по умолчанию сохраняются.

Тесты A1-A5 (из ДЗ): контролируемая заглушка модели; живая модель не используется.
