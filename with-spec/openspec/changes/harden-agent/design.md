## Context

`agent.py` — один файл без зависимостей. Инструменты синхронные и локальные; модель подставляется функцией `model_fn(history, tools)`, поэтому в тестах легко использовать заглушку.

## Goals / Non-Goals

**Goals:** R1–R6 без изменения внешнего интерфейса CLI и инструментов.
**Non-Goals:** новые инструменты, сеть в тестах, изменение `config.json`, `docs.json`, текста `SYSTEM`.

## Decisions

- **Обёртка `call_tool`**: `run_agent` вызывает `call_tool(name, arguments, docs)`, которая ловит `Exception` вокруг `run_allowed_tool` и возвращает `tool_failure`. Альтернатива — try/except внутри `run_allowed_tool`; отвергнута, чтобы тест мог подменить `run_allowed_tool` и проверить обёртку.
- **`status`** вычисляется как `"error"`, если в результате есть ключ `error`, иначе `"ok"`.
- **`missing_ids`**: `not_found` несёт `doc_id` в поле `error`, оттуда агент собирает множество; `read_ids` — из успешных `read_doc`; оба выводятся отсортированными.
- **R4**: непрочитанные ссылки = цитируемые ID (шаблон `[D01:…]`) минус `read_ids`. Счётчик замечаний един для всех причин (нет search, непрочитанные источники). Замечание называет конкретные ID. Третье нарушение → `unverified_sources`, `answer = None`. Проверка выполняется только при финальном ответе, лимиты моделей продолжают действовать, поэтому `budget_exhausted` возможен раньше.
- **Единая точка выхода** `finish(stop_reason, answer, ...)` собирает все поля результата, чтобы `read_ids`/`missing_ids`/`tool_errors` были во всех ветках.

## Risks / Trade-offs

- Регулярное выражение цитат распознаёт только `[Dxx:` и `(Dxx:`; ссылки без номеров строк не проверяются — как и в исходном коде.
- Перехват `Exception` может скрыть программную ошибку; она остаётся видимой в `tool_failure.message` и `tool_errors`.
